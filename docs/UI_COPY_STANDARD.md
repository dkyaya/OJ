# UI Copy Standard

## Voice

Use direct product language. A user should know what a control does before pressing it.

- Headings use title case and normally contain one to six words.
- Buttons start with an action: Build Idea, Add Catalyst, Record Entry, Save Review, Export Journal.
- Supporting text states the object or consequence in one sentence.
- Empty states explain what appears there and offer one relevant action.
- Status text describes application state: Local Draft, Saving, Saved Offline, Saved to OJ, Conflict.
- Unknown trading values remain `TBD`; never infer a quote, contract count, fill, risk, or outcome.

Avoid vague helper phrases, inspirational copy, metaphors, and internal architecture terms in the interface. GitHub, pull requests, formalization jobs, and Obsidian do not appear in the ordinary save workflow. Obsidian appears only where the user chooses a Markdown export.

The `copy:check` script blocks retired workflow phrases from frontend source. Human review is still required for clarity and title case.
